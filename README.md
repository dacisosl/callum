# Padlet-Lite

링크, 이미지, PDF를 칼럼으로 정리하는 개인용 보드입니다. Next.js로 만들었고 Supabase(Auth, Postgres, Storage)를 사용합니다. 배포는 Vercel이 GitHub `main` 브랜치를 지켜보다가 push마다 자동으로 합니다.

- 저장소: https://github.com/dacisosl/callum
- 데이터베이스 스키마: `supabase/schema.sql`

## 주요 기능

- 여러 보드와 칼럼 생성·이름 변경·복제·삭제
- 카드 작성·수정·복제·삭제
- 카드의 칼럼 내부 정렬, 칼럼 간 이동, 칼럼 순서 변경
- 이미지와 PDF 첨부 및 카드 타일 미리보기 (이미지, PDF 첫 페이지, 유튜브 썸네일). 편집창에서 Ctrl+V로 클립보드 이미지를 바로 첨부
- PDF는 올릴 때 브라우저에서 첫 쪽을 JPEG 썸네일로 만들어 함께 저장합니다(`lib/pdf-render.ts`, pdf.js). 카드 타일은 이 썸네일을 쓰고, 휴대폰 뷰어는 쪽마다 캔버스로 그립니다. 안드로이드·카카오톡 인앱 브라우저는 PDF `<iframe>`을 파일 다운로드로 넘겨 버리기 때문입니다. 썸네일 없이 올라간 옛 PDF는 주인이 보드를 열면 자동으로 채워지고, 그 전까지 휴대폰에서는 아이콘 자리표시로 보입니다.
- 큰 이미지는 올리기 전에 브라우저에서 자동으로 줄임 (긴 쪽 2000px, JPEG 품질 0.85, 투명 PNG는 유지, GIF·SVG·PDF는 그대로)
- 홈 화면에 무료 사용량 대시보드: 파일 저장 공간(1GB)과 보드 데이터(500MB)를 링 미터로, 보드·카드·첨부·댓글 수를 함께 표시
- 어느 카드도 쓰지 않는 첨부 파일은 자동으로 정리됩니다. 홈 화면 사용량 패널의 휴지통 버튼으로 바로 정리할 수도 있습니다
- 카드를 누르면 크게 보는 뷰어 모달: 이미지 전체 화면, PDF 뷰어(데스크톱은 브라우저 내장 뷰어, 휴대폰은 쪽 단위 렌더링), 유튜브·비메오 바로 재생
- 링크 제목·설명·대표 이미지 미리보기
- 카드마다 배경 색 선택, 칼럼마다 제목 막대와 `+` 버튼 색 선택 (기본값은 모든 칼럼이 같은 색)
- 보드별 댓글 기능 켜기/끄기. 공유받은 사람은 이름을 적고 댓글을 남길 수 있고 주인은 삭제할 수 있습니다
- 보드별 글쓰기 허용 켜기/끄기. 켜면 공유받은 사람도 그 보드에 카드를 올릴 수 있습니다
- 공유받은 사람은 자기가 올린 글을 나중에 고치거나 지울 수 있습니다. 글을 올린 그 브라우저에서만 됩니다
- **질문 섹션**: 칼럼에 질문 하나를 고정해 두면, 그 칼럼에서 쓰는 카드가 그 질문에 대한 답이 됩니다. 칼럼을 만들 때 질문을 넣거나, 기존 칼럼의 메뉴에서 질문 섹션으로 바꿀 수 있습니다. 답을 쓰는 사람은 편집창 맨 위에 붙어 있는 질문을 보면서 작성합니다
- 댓글이 있는 카드는 타일에 첫 댓글이 미리보기로 보입니다
- 카드 검색, 칼럼 접기, 자동 저장, 이동·삭제 실행 취소
- 보고 있는 보드가 주소에 남아(`?board=...`) 새로고침해도 그 보드가 다시 열립니다. 뒤로가기로 홈에 갑니다
- 다른 사람이 글을 올리거나 고치면 새로고침 없이 화면에 나타납니다
- 보드별 읽기 전용 공유 링크. 홈 화면에서 공유 중인 보드의 링크를 한눈에 보고 복사·중지
- 모바일 터치와 키보드 드래그 조작
- 동영상 파일 업로드는 차단되고, 유튜브·비메오 URL은 카드 뷰어에서 재생됩니다

## 로컬 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 서버 없이 화면만 확인하려면 `.env.local`에 `NEXT_PUBLIC_DEMO_MODE=1`을 넣으면 브라우저 로컬 데모 모드로 실행됩니다.

## 접속 주소

Vercel은 배포마다 `callum-xxxxxxxx-....vercel.app` 같은 **배포 전용 주소**도 만들지만, 그 주소는 그 배포 시점의 코드에 고정되어 이후 변경이 반영되지 않습니다. 고정 도메인은 Vercel 대시보드 → 프로젝트 → Settings → Domains 에 있습니다(`callum-<팀>.vercel.app` 또는 연결한 도메인).

앱이 만드는 공유 링크와 링크 미리보기 주소는 현재 열려 있는 주소와 관계없이 **항상 고정 도메인**으로 만들어집니다(`lib/site-url.ts`). 기준은 `NEXT_PUBLIC_SITE_URL` → Vercel이 넣어 주는 `NEXT_PUBLIC_VERCEL_PROJECT_PRODUCTION_URL` → 코드에 적힌 기본값 `https://callum-eight.vercel.app` 순서입니다. 나만의 도메인을 연결하면 Vercel 값이 그 도메인으로 바뀌고, 다른 주소를 쓰고 싶으면 `NEXT_PUBLIC_SITE_URL`에 넣으면 됩니다. 로컬 개발 서버(`localhost`)에서만 현재 주소를 그대로 씁니다.

`proxy.ts`는 프로덕션에서 배포 전용 주소로 들어온 요청을 고정 도메인으로 308 리디렉션하므로, 예전에 보낸 배포 전용 링크도 최신 화면으로 연결됩니다.

## 화면 구성

- **홈**: 맨 위에 무료 사용량 대시보드가 있습니다. 파일 저장 공간은 내 폴더와 손님 폴더의 파일 크기를 직접 더해 세고, 보드 데이터는 `get_my_usage` 함수가 돌려줍니다. 홈을 보는 동안 1분마다 다시 세며 새로 고침 버튼도 있습니다. 한 달 전송량(5GB)은 클라이언트에서 셀 수 없어 Supabase 대시보드 링크로 안내합니다. 그 아래에 내 보드 전체를 카드로 보여줍니다. 보드 검색, 새 보드, 이름 변경, 삭제를 할 수 있습니다. 공유 중인 보드가 있으면 맨 위에 "공유 중인 보드" 목록이 나타나 링크를 바로 복사하거나 공유를 중지할 수 있고, 보드 메뉴에서 링크를 새로 만들 수도 있습니다.
- **보드**: 칼럼마다 제목 막대 아래에 `+` 버튼이 있고, 새 카드는 맨 위에 추가됩니다. 질문 섹션은 제목 막대에 물음표 표시가 붙고, `+` 대신 "답변 쓰기" 버튼이 나옵니다. 왼쪽 위 로고나 보드 이름 메뉴의 "모든 보드 보기"로 홈에 돌아갑니다. 칼럼 메뉴(`…`)에서 이름과 색을 바꿉니다.
- **카드 타일**: 맨 위에 미리보기(첨부 이미지·PDF 첫 페이지·동영상 썸네일·링크 대표 이미지)가 2:1 높이로 들어가고, 그 아래 제목, 사이트와 링크 제목, 본문, 작성자·작성 시각·댓글 수 줄이 이어집니다. 본문의 줄바꿈은 그대로 유지되고 링크 썸네일에는 주소 배지가 붙습니다. 공유받은 사람이 올린 카드에는 손님 표시가 붙습니다.
- **링크 편집**: 주소를 넣고 저장하면 미리보기를 누르지 않아도 저장 시 자동으로 받아옵니다. 주소 칸을 비우거나 "링크 제거"를 누르고 저장하면 링크가 카드에서 빠집니다.
- **카드 뷰어**: 카드를 누르면 공유받은 사람이 보는 것과 같은 화면이 뜹니다. 주인에게는 오른쪽 위에 편집 버튼이 있고, 카드 메뉴의 "수정"으로 바로 편집 모달을 열 수도 있습니다. 보드의 댓글 기능이 켜져 있으면 뷰어 아래에 댓글란이 나타납니다.
- **공유 보기**: `?share=토큰` 주소로 열리며 로그인 없이 읽기 전용으로 표시됩니다. 댓글이 켜진 보드라면 댓글은 남길 수 있습니다. 이 주소를 카카오톡·슬랙 등에 붙이면 보드 제목, 칼럼·카드 수, 보드 제목이 그려진 미리보기 이미지(`/api/og`)가 링크 미리보기로 붙습니다. 휴대폰에서는 보드 위에 칼럼 탭이 나타나 눌러서 칼럼 사이를 오갈 수 있고, 카드의 썸네일을 눌러도 카드가 열립니다.

### 질문 섹션

- 칼럼 메뉴(`…`)의 "질문 섹션으로 만들기"로 설정하거나, 칼럼 추가 폼의 "질문 (선택)" 칸을 채워 만듭니다. 질문은 500자까지입니다.
- 질문은 칼럼 맨 위에 고정되며 기본 3줄(휴대폰 2줄)까지 보이고, 길면 "더 보기"로 펼칩니다.
- 질문 섹션에서는 제목이 선택입니다. 비워 두고 답만 쓰면 쓴 사람 이름이 카드 제목이 됩니다. 보통 칼럼은 지금처럼 제목이 필수입니다.
- 카드 뷰어에는 그 칼럼의 질문이 답변 위에 함께 보입니다.
- 질문을 해제하면 보통 칼럼으로 돌아가고 답변 카드는 그대로 남습니다. 토스트의 "실행 취소"로 되돌릴 수 있습니다.
- 칼럼을 복제하면 질문과 답변이 함께 복제됩니다.
- 공유받은 사람이 답을 올리려면 보드의 "읽기 전용 링크"와 "공유받은 사람의 글쓰기"가 모두 켜져 있어야 합니다. 꺼져 있으면 질문 설정 창이 알려 주고 공유 설정을 바로 열 수 있습니다.
- 데이터는 칼럼의 `question` 필드에 들어갑니다. 보드 전체가 `boards.data` JSONB 한 덩어리로 저장되므로 **Supabase 스키마를 다시 실행할 필요가 없습니다.**

### 손님 카드 보호

주인 화면은 보드 전체를 통째로 저장합니다. 예전에는 주인이 보드를 열어 둔 사이 손님이 올린 카드가 다음 저장 때 덮어써져 사라졌습니다. 이제 글쓰기가 켜진 보드는 저장 직전에 서버 쪽 데이터를 읽어, 내 화면에 없는 손님 카드를 되살려 함께 저장합니다(`lib/supabase-client.ts`의 `withGuestCards`). 주인이 방금 지운 카드는 되살아나지 않습니다.

### 손님이 자기 글을 수정하기

손님은 로그인을 하지 않아 "이 글을 쓴 사람이 나"라는 것을 증명할 방법이 없습니다. 그래서 글을 올릴 때
브라우저에 비밀 열쇠를 저장하고(`pillar-card-keys-v1`), 서버에는 그 열쇠의 SHA-256 지문만
카드의 `editKeyHash` 에 남깁니다. 수정할 때 열쇠를 함께 보내면 서버가 지문을 다시 계산해 맞을 때만
통과시킵니다(`update_shared_card`). 지문은 공유 링크로 읽히지만 지문에서 열쇠를 되돌릴 수 없어
남의 글은 고칠 수 없습니다.

- 카드를 눌러 크게 보면 자기 글에만 "내 글 수정" 과 "삭제" 가 보입니다. 제목, 내용, 링크, 첨부를 바꿀 수 있습니다.
- 이름과 올린 시각, 칼럼 위치는 바뀌지 않습니다.
- 삭제는 되돌릴 수 없습니다(주인의 카드 삭제와 달리 실행 취소가 없습니다). 첨부 파일 자체는 저장소에 남고
  보드를 지울 때 함께 정리됩니다. 손님에게는 저장소 삭제 권한이 없기 때문입니다.
- **글을 올린 그 브라우저에서만** 수정할 수 있습니다. 다른 기기로 옮기거나 브라우저 데이터를 지우면
  열쇠가 사라져 수정할 수 없습니다. 이 기능이 생기기 전에 올라간 글도 열쇠가 없어 수정할 수 없습니다.
- 별도 설정은 없습니다. "공유받은 사람의 글쓰기"가 켜져 있으면 자동으로 됩니다.
- 이 기능을 쓰려면 **`supabase/guest-cards.sql`** 을 SQL Editor에서 한 번 실행해야 합니다
  (`supabase/schema.sql` 전체를 실행해도 같습니다). 실행하지 않아도 글 올리기와 파일 첨부는
  예전처럼 동작합니다. 앱이 새 함수가 없는 것을 알아채면 예전 방식으로 올리고, 그 글은 수정만
  안 됩니다.

### 손님이 이미지·PDF를 못 올릴 때

공유 설정에서 글쓰기를 켰는데도 손님의 파일 업로드가 거부된다면, 저장소 정책이 옛 버전입니다.
**`supabase/fix-guest-uploads.sql`** 을 SQL Editor에 붙여 넣고 실행하세요. 이 문제만 고치는 짧은
스크립트라 붙여넣기가 잘릴 걱정이 없습니다. `supabase/schema.sql` 전체를 실행해도 같은 내용이 들어갑니다.

### `unterminated dollar-quoted string` 오류가 날 때

Supabase 대시보드의 SQL Editor는 `select ... into 변수` 를 "새 표를 만드는 SELECT INTO"로 오해해,
함수 본문 한가운데에 `ALTER TABLE 변수 ENABLE ROW LEVEL SECURITY;` 를 몰래 끼워 넣습니다.
그러면 `$$` 로 감싼 본문이 중간에서 끊겨 이 오류가 납니다. 오류 메시지 안에 그 `ALTER TABLE` 줄이
같이 보이면 이 경우입니다.

그래서 이 저장소의 함수들은 `select ... into` 대신 `변수 := (select ...)` 대입문만 씁니다.
새 함수를 추가할 때도 같은 규칙을 지켜야 합니다.

원인은 이렇습니다. 예전 정책은 손님 업로드를 허용할지 판단할 때 정책 안에서 `boards` 테이블을
직접 조회했습니다. 그런데 정책 안의 조회에도 `boards`의 RLS가 그대로 걸리고, `boards`는
로그인한 주인만 읽을 수 있습니다. 손님은 익명(anon)이라 조회 결과가 언제나 0건이 되어,
공유와 글쓰기를 아무리 켜 두어도 업로드가 전부 거부되었습니다. 지금은 RLS를 우회하는
`board_accepts_guest_files` 함수(security definer)로 확인하므로 정상 동작합니다.

정책이 최신인지 확인하려면 SQL Editor에서 실행해 보세요. 공유와 글쓰기를 켠 보드는 마지막 열이
`true`로 나와야 합니다.

```sql
select id, title, share_enabled, public.board_accepts_guest_files(id)
from public.boards order by updated_at desc;
```

`share_enabled`가 true인데 마지막 열이 false면 그 보드의 글쓰기 허용이 꺼져 있는 것이니,
앱의 공유 설정에서 켜 주세요.

### 쓰이지 않는 첨부 파일 정리

첨부 파일은 저장소에 올라가고 카드에는 그 경로만 적힙니다. 카드가 사라져도 파일은 남아 무료 1GB를
갉아먹습니다. 카드 삭제, 편집창에서 첨부 빼기, 손님의 글 삭제, 저장하지 않고 편집창 닫기가 모두
이런 파일을 남깁니다.

- **자동**: 보드를 열면 잠시 뒤 그 보드의 파일을 훑어, 어느 카드도 가리키지 않고 **올라간 지 24시간이
  지난** 파일을 지웁니다. 보드마다 화면을 여는 동안 한 번만 돕니다. 지운 게 있을 때만 알려 줍니다.
- **수동**: 홈 화면 사용량 패널의 휴지통 버튼을 누르면 내 보드 전체를 돌며 **10분이 지난** 파일까지
  정리합니다. 확인 창을 한 번 거치고, 끝나면 사용량을 다시 셉니다.

지우면 안 되는 파일을 지키기 위해 두 가지를 지킵니다. 첫째, 나이 기준을 둡니다. 편집창에 붙여 둔
파일은 저장소에는 있지만 아직 카드에는 없기 때문입니다. 둘째, 판단 기준이 되는 보드를 서버에서 새로
읽습니다. 손님이 방금 올린 글이 내 화면에는 아직 없을 수 있기 때문입니다. 카드를 복제하면 여러 카드가
같은 파일을 가리키므로, 참조는 집합으로 모아 한 카드를 지워도 파일이 남게 합니다.

규칙 자체는 `lib/attachment-sweep.ts` 에 저장소와 무관한 순수 함수로 두어 따로 시험합니다.
실제 삭제는 `lib/supabase-client.ts` 의 `sweepOrphanAttachments` 가 맡습니다. 주인에게 필요한
저장소 권한은 이미 있어 **SQL 변경은 없습니다.**

한계: 이미 지워진 보드의 `guest/{보드ID}/` 폴더에 남은 파일은 이 방식으로 닿지 않습니다. 보드가 없으면
훑을 대상을 정할 수 없기 때문입니다. 보드를 지울 때 카드가 가리키던 파일은 `removeBoard` 가 이미
정리하므로, 남는 것은 그 보드에서 이미 고아였던 파일뿐입니다.

### 실시간 반영

새로고침하지 않아도 남이 올린 글이 화면에 나타납니다. 세 가지가 함께 동작합니다.

1. **알림**: 누가 글을 올리거나 고치거나 댓글을 달면, 같은 보드를 보고 있는 사람들에게 Supabase
   Realtime 방송으로 "바뀌었다"고 알립니다. 받은 쪽은 바로 다시 읽습니다. 표 구독이 아니라 방송이라
   Supabase 대시보드에서 따로 켤 설정도, 실행할 SQL 도 없습니다.
2. **화면 복귀**: 탭으로 돌아오거나 창이 다시 활성화되면 한 번 확인합니다.
3. **주기 확인**: 화면이 보이는 동안 60초마다 한 번 확인합니다. 방송이 막힌 환경을 위한 보조 수단이며,
   숨겨진 탭에서는 돌지 않아 통신량을 아낍니다.

내가 카드를 쓰는 중이거나(편집창이 열려 있음), 아직 저장되지 않은 변경이 있거나, 카드를 끌고 있는
동안에는 다시 읽지 않습니다. 남의 글이 내 작업을 덮어쓰지 않게 하기 위해서입니다.

## Supabase 준비

1. https://supabase.com 에서 프로젝트를 만듭니다. 리전은 `Northeast Asia (Seoul)`을 권장합니다.
2. SQL Editor에 `supabase/schema.sql` 내용을 붙여 넣고 실행합니다. 테이블, RLS 정책, 공유 조회 함수, 첨부 버킷이 한 번에 만들어집니다.
3. Authentication → Users → Add user에서 쓸 계정을 직접 만듭니다. 앱에는 로그인 화면만 있고 가입 화면은 없습니다. Providers → Email의 **Confirm email**을 켜 두었다면 메일 인증을 마쳐야 로그인되므로, 혼자 쓴다면 꺼 두는 편이 간단합니다.
4. Project Settings → API의 **Project URL**과 **anon public** 키를 `lib/supabase-config.ts`의 `defaults`에 넣습니다. 로컬에서만 다른 프로젝트를 쓰려면 `.env.local`의 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`가 우선합니다.

anon 키는 브라우저에 노출되는 공개값입니다. 접근 제어는 `schema.sql`의 행 수준 보안(RLS) 정책이 담당합니다.

## Vercel 배포

1. https://vercel.com 에서 GitHub로 로그인하고 Add New → Project → `dacisosl/callum`을 Import 합니다.
2. Framework는 Next.js로 자동 감지됩니다. 환경 변수는 필요 없습니다. Deploy를 누릅니다.

이후 GitHub 웹에서 코드를 고쳐 커밋하면 그대로 배포까지 이어집니다.

## 무료 요금제 참고

Supabase 무료 프로젝트는 일주일간 요청이 없으면 자동으로 일시 중지됩니다. 데이터는 유지되며 대시보드에서 Restore를 누르면 1분 안에 다시 켜집니다.

## 파일 제한

- 파일당 최대 30MB (버킷 설정과 앱 양쪽에서 제한). 한도를 바꾸려면 `supabase/schema.sql`의 버킷 `file_size_limit`과 `app/board-app.tsx`의 `MAX_CLOUD_FILE`을 함께 고치고 SQL을 다시 실행합니다
- 허용 형식: 이미지, PDF
- 동영상 파일은 선택 단계와 업로드 처리 단계에서 거부됩니다

## 공유받은 사람의 글쓰기

공유 대화상자의 "공유받은 사람의 글쓰기" 스위치로 보드마다 따로 켭니다. 기본값은 꺼짐이라 기존 공유 링크는 그대로 읽기 전용입니다.

- 켜면 공유 화면에도 칼럼의 `+` 버튼이 나타납니다.
- 손님은 이름, 제목, 내용, 링크와 함께 이미지·PDF도 첨부할 수 있습니다(파일당 30MB, 카드당 10개). 파일은 `attachments` 버킷의 `guest/{보드ID}/` 경로에 올라가며, 저장소 정책이 그 보드가 공유 중이고 글쓰기가 켜져 있는지 확인합니다. 주인은 자기 보드의 손님 파일을 지울 수 있습니다.
- 공유 링크를 아는 사람은 누구나 파일을 올릴 수 있으므로, 글쓰기를 켜 두면 저장 용량이 그만큼 쓰일 수 있습니다. 모르는 사람에게 퍼졌다면 글쓰기를 끄거나 링크를 새로 만드세요.
- 손님이 올린 카드에는 이름표가 붙어 주인이 구분할 수 있습니다. 주인은 그 카드를 여느 카드처럼 옮기고 고치고 지울 수 있습니다.
- 저장은 `add_shared_card` 함수가 맡습니다. 토큰이 맞고 글쓰기가 켜져 있으며 칼럼이 실제로 있을 때만 통과하고, 제목 120자·내용 3000자·보드당 2000장 상한이 걸려 있습니다. 첨부는 우리 저장소의 `guest/{보드ID}/` 경로에 올라간 이미지·PDF만 받습니다.

주인이 보드를 열어 둔 채로 손님이 카드를 올리면, 주인 화면은 그 카드를 모른 채로 저장하다가 덮어쓸 수 있습니다. 손님 카드가 보이지 않으면 주인 화면을 새로고침하세요.

## 댓글

공유 대화상자나 보드 이름 메뉴에서 보드별로 댓글을 켜고 끕니다. 설정은 보드 데이터의 `commentsEnabled`에 저장되고, 댓글은 `card_comments` 테이블에 따로 저장됩니다.

- 보드 주인은 RLS 정책으로 자기 보드의 댓글을 읽고 쓰고 삭제합니다.
- 공유 링크로 보는 사람은 `get_shared_comments`, `add_shared_comment` 함수로만 읽고 씁니다. 두 함수는 토큰이 맞고 `commentsEnabled`가 true인 보드에서만 동작하며, 주인의 사용자 ID는 노출하지 않습니다.
- 댓글을 끄면 기존 댓글은 지워지지 않고 숨겨질 뿐이며, 다시 켜면 그대로 보입니다.
- 이미 스키마를 적용한 프로젝트라면 `supabase/schema.sql`을 다시 한 번 통째로 실행해 테이블과 함수를 추가하세요. 공유 글쓰기용 `add_shared_card`, 사용량용 `get_my_usage` 함수도 같은 파일에 들어 있습니다.

## 공유 방식

공유 링크는 보드마다 따로 생깁니다. 공유를 켜면 그 보드에 무작위 `shareToken`이 생기고, 공유 링크(`?share=토큰`)는 `get_shared_board` 함수로 해당 보드 하나만 읽어옵니다. 공유 목록을 열거하는 경로는 없습니다. 공유를 끄거나 링크를 재발급하면 기존 링크는 더 이상 조회되지 않습니다.

공유 링크에는 만료 기간이 없습니다. 링크를 끊으려면 홈 화면의 공유 목록이나 공유 대화상자에서 공유를 중지하거나, 링크를 새로 발급해 기존 링크를 무효로 만듭니다.

첨부파일은 공개 버킷의 URL을 사용합니다. 공유를 끈 뒤에도 파일 주소를 이미 아는 사람은 계속 열 수 있습니다. 이를 막아야 한다면 버킷을 비공개로 바꾸고 서명 URL을 발급하는 구조로 바꿔야 합니다.

## 프로젝트 구조

- `app/board-app.tsx`: 보드 UI와 상호작용 전체
- `proxy.ts`: 배포 전용 주소를 고정 도메인으로 리디렉션
- `lib/site-url.ts`: 공유 링크·미리보기에 쓰는 고정 도메인
- `lib/pdf-render.ts`: PDF 첫 쪽 썸네일 생성과 쪽 단위 캔버스 렌더링(pdf.js legacy 빌드)
- `app/api/og/route.tsx`: 공유 링크의 미리보기 이미지. 보드 제목에 쓰인 글자만 Google Fonts에서 받아 한글을 그립니다
- `lib/shared-board-server.ts`: 서버(메타데이터, OG 이미지)에서 공유 보드를 읽는 함수와 배포 도메인 계산
- `app/api/link-preview/route.ts`: 링크 메타데이터 수집 (Vercel 서버 함수로 실행). Google 문서·설문·드라이브, Gemini처럼 로그인이 필요한 서비스는 대표 이미지를 받을 수 없어 화면에서 서비스 표지를 보여 줍니다. og 태그가 없으면 `link rel="image_src"`, JSON-LD, 본문 첫 이미지 순으로 찾고, 그래도 없으면 아이콘을 내려 줍니다. 화면에서는 대표 이미지가 없거나 깨지면 WordPress.com mShots 화면 캡처(`s0.wp.com/mshots`)를, 그것도 안 되면 아이콘 표지를 보여 줍니다. 캡처는 처음 요청 때 "생성 중" 그림이 먼저 오고 잠시 뒤부터 실제 화면이 나옵니다
- `lib/supabase-client.ts`: 로그인, 보드 저장·조회, 첨부 업로드
- `lib/supabase-config.ts`: Supabase URL과 anon 키
- `lib/board-types.ts`: 데이터 형식
- `supabase/schema.sql`: 테이블, RLS 정책, 공유 함수, 버킷
